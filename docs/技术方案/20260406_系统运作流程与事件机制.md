# 系统运作流程与事件机制

本文档描述 AutoGLM Android Assistant 的整体架构、核心运作流程及事件处理机制，适合希望快速理解项目技术结构的开发者阅读。

---

## 一、整体架构

### 1.1 双应用架构

```
┌──────────────────────────────────────────────────────────────────┐
│                    主应用（app module）                            │
│                                                                  │
│  ┌─────────────┐  ┌──────────────────┐  ┌───────────────────┐  │
│  │  MainActivity │  │  WakeWordService  │  │  PhoneAgent       │  │
│  │  (Compose UI) │  │  (前台服务)       │  │  (任务执行核心)   │  │
│  │              │  │                  │  │                   │  │
│  │  状态订阅     │  │  唤醒词检测       │  │  截图→推理→操作  │  │
│  │  消息路由     │  │  语音识别         │  │  循环直至完成     │  │
│  │  对话历史     │  │  意图识别         │  │                   │  │
│  └─────────────┘  └──────────────────┘  └───────────────────┘  │
│         ▲               │ StateFlow                              │
│         └───────────────┘                                       │
└────────────────────────────┬────────────────────────────────────┘
                              │ AIDL IPC
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│                    Provider 应用（provider module）               │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  AccessibilityProviderService（无障碍服务）               │   │
│  │  - 获取 UI 层级树（UIHierarchy）                          │   │
│  │  - 执行点击 / 输入 / 滑动操作                             │   │
│  └──────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────┘
```

**设计原因**：无障碍服务独立部署，主应用不直接包含 `AccessibilityService`，降低被目标应用（微信/支付宝等）检测的风险，同时允许 Provider 独立更新。

### 1.2 核心组件职责

| 组件 | 位置 | 职责 |
|------|------|------|
| `WakeWordService` | app/service | 前台服务：唤醒词检测、语音识别、任务生命周期管理 |
| `PorcupineWakeEngine` | app/voice/wake | 离线唤醒词检测，基于 Picovoice Porcupine SDK |
| `PhoneAgent` | app/core/agent | 执行循环：截图 → 模型推理 → 动作解析 → 调用无障碍/Shell |
| `SmartCoordinator` | app/core/planner | 任务规划：拆解子任务、执行监督、生成总结 |
| `IntentRecognizer` | app/ai | 意图识别：将自然语言语音匹配到快捷指令模板 |
| `ActionExecutor` | app/core/action | 动作执行：无障碍服务（优先）→ ADB Shell（降级）|
| `MainActivity` | app | Compose UI 宿主：订阅 StateFlow，路由消息到对话历史 |
| `AccessibilityProviderService` | provider | 无障碍操作实际执行方，通过 AIDL 与主应用通信 |

## 二、语音唤醒触发流程

```
用户说出唤醒词
      │
      ▼
PorcupineWakeEngine.AudioRecord 采样
      │ 检测到唤醒词
      ▼
WakeWordService.onWakeWord()
  - 停止采样（stopListening）
  - 振动反馈
  - 启动 STT（startSpeechRecognition）
      │
      ▼
STT 识别用户指令（豆包输入法 / 讯飞 API）
      │ 识别完成
      ▼
WakeWordService.handleSpeechResult(text)
  - _lastRecognizedText.value = text        ← 通知 UI 线程
  - _serviceState.value = EXECUTING_TASK
  - phoneAgent.run(text, ...)               ← 启动任务（协程）
      │
      ▼
MainActivity.LaunchedEffect(lastRecognizedText)
  - createNewConversation() 如有必要
  - addMessage(用户消息气泡)
  - taskOwnerConversationId = currentConversation.id  ← 锁定任务对话
  - navigate("chat") 如不在 chat 页面
```

## 三、意图识别与快捷指令路由

当`prefs.intentRecognizerEnabled == true`时，语音文字进入意图识别流程：

```
语音文字 text
      │
      ▼
IntentRecognizer.recognize(text, shortcuts)
  构建 prompt：
    - 系统提示词（要求 LLM 返回 JSON 格式）
    - 用户消息：所有快捷指令（标题 + 参数占位符列表）+ 用户输入文字
      │
      ▼ 一次 LLM 调用，同时完成：匹配识别 + 参数抽取
      │
  LLM 返回 JSON:
    {
      "matched": true/false,
      "shortcutId": "xxx",
      "parameters": { "商品A": "小米手机", "商品B": "华为手机" }
    }
      │
      ▼
  matchedShortcut.fillParameters(parameters)
  → "比较 {商品A} 和 {商品B} 的价格"
  → "比较 小米手机 和 华为手机 的价格"
      │
  ┌───┴───────────────────────────────────────┐
  │ matched == true                            │ matched == false
  ▼                                           ▼
使用 filledPrompt 替代原始 text           直接使用原始 text
（快捷指令模板 + 参数由 LLM 从语音中抽取）
      │                                       │
      └───────────────┬───────────────────────┘
                      ▼
              phoneAgent.run(finalPrompt, ...)
```

关键点：**LLM 一次调用同时完成"匹配哪条快捷指令"和"从语音中抽取参数值"两件事**，参数值来源于用户的原始语音内容。

快捷指令在首页配置（设置 → 快捷指令），每条包含：
- **标题**：意图匹配时的识别依据
- **提示词模板**：支持 `{参数名}` 占位符，参数值由意图识别 LLM 从用户语音中抽取
- **启用规划 / 启用优化器**：各快捷指令独立控制

## 四、任务执行主循环（PhoneAgent）

```
PhoneAgent.run(task, useCoordinator, ...)
      │
      │ useCoordinator == true
      ▼
SmartCoordinator.execute()
  ┌─ 优化提示词（PromptOptimizer）
  ├─ 规划子任务列表（TaskPlanner）
  ├─ 循环执行每个子任务
  │       │
  │       ▼
  │   executeSubTask(subtask)
  │       │
  │       ▼
  │   ┌──────────────────── 执行主循环 ───────────────────────┐
  │   │  step = 0                                             │
  │   │  while step < maxSteps                                │
  │   │    ├─ 截图（ScreenCapture）                           │
  │   │    ├─ 构建消息（MessageBuilder）                      │
  │   │    ├─ 调用模型 API（ModelClient）                     │
  │   │    │     ├─ onThinking → WakeWordService → StateFlow  │
  │   │    │     └─ onAction  → WakeWordService → StateFlow   │
  │   │    ├─ 解析动作（ActionParser）                        │
  │   │    ├─ onBeforeAction（隐藏悬浮窗）                    │
  │   │    ├─ 执行动作（ActionExecutor）                      │
  │   │    │     ├─ 无障碍服务（优先）                        │
  │   │    │     └─ ADB Shell（降级）                         │
  │   │    ├─ onAfterAction（恢复悬浮窗）                     │
  │   │    └─ 检查是否 FINISH                                 │
  │   │  end while                                            │
  │   └───────────────────────────────────────────────────────┘
  │       │
  │       ▼
  │   SubTask 执行监督（SupervisionResult）
  │
  └─ 生成任务总结（Summary）
      │
      ▼
onResult(summaryText) → WakeWordService → _agentMessage → UI
```

## 五、事件传递机制（Service → UI）

`WakeWordService` 通过 `StateFlow` 向 `MainActivity` 推送事件，UI 线程通过 `LaunchedEffect` 订阅：

```
WakeWordService（Service 线程）
  _agentMessage: MutableStateFlow<AgentMessage?>
  _coordinatorMessage: MutableStateFlow<CoordinatorMessage?>
  _serviceState: MutableStateFlow<ServiceState>
  _lastRecognizedText: MutableStateFlow<String>
         │
         │ collectAsState()
         ▼
MainScreen（Compose UI 线程）
  LaunchedEffect(agentMessage?.value) { ... }
  LaunchedEffect(coordinatorMessage?.value) { ... }
  LaunchedEffect(lastRecognizedText?.value) { ... }
```

### 5.1 消息类型定义

**AgentMessage.type**：

| 类型 | 触发时机 | UI 表现 |
|------|----------|---------|
| `THINKING` | 模型推理中，流式输出思考过程 | 临时气泡，被下一条 ACTION 替换 |
| `ACTION` | 确定操作指令 | 合并 THINKING+ACTION 显示为单气泡 |
| `RESULT` | 任务完成，最终结果 | 永久气泡，解除 taskOwnerConversationId |

**CoordinatorMessage.type**：

| 类型 | 触发时机 |
|------|----------|
| `OPTIMIZER_STREAMING` / `OPTIMIZER_COMPLETE` | 提示词优化中/完成 |
| `PLANNING_STREAMING` / `PLAN_COMPLETE` | 任务规划中/完成 |
| `SUBTASK_CARD` | 每个子任务卡片 |
| `SUBTASK_START` | 开始执行某子任务 |
| `SUPERVISION_RESULT` | 子任务执行监督结果 |
| `COORDINATOR_THINKING` | 协调器思考中 |
| `COORDINATOR_STEP` | 当前步数 / 最大步数 |
| `SUMMARY_STREAMING` / `SUMMARY_COMPLETE` | 总结生成中/完成 |
| `CLEAR` | 重置所有状态 |

### 5.2 消息路由（跨对话防污染）

任务发起时锁定 `taskOwnerConversationId`，确保消息始终写入发起任务的原始对话：

```
任务发起（语音/快捷指令/手动输入）
  taskOwnerConversationId = currentConversation.id

addMessageToTask(message)
  if taskOwnerConversationId == currentConversation.id
    → addMessage(message)         // 正常写入当前显示对话
  else
    → ownerConv.messages.add()    // 后台写入原始对话，不影响当前显示

RESULT 消息接收后
  taskOwnerConversationId = null   // 解锁
```

## 六、快捷指令系统

快捷指令类似 Skill，在首页展示并可一键执行：

```
HomeScreen 快捷指令卡片
  onShortcutClick(prompt, enablePlanning, enableOptimizer)
      │
      ▼
  createNewConversation()
  addMessage(用户消息气泡)
  taskOwnerConversationId = currentConversation.id
  navigate("chat")
  checkAndExecute(prompt, ...)
      │
      ▼
  WakeWordService.executeTask(prompt, ...)
      │
      ▼
  PhoneAgent.run(...)
```

可在设置中批量管理快捷指令，每条支持独立配置是否启用规划器和优化器。

## 七、语音识别（STT）策略

| 策略 | 实现类 | 特点 |
|------|--------|------|
| IME 语音（豆包键盘）| `ImeVoiceSttHelper` | 利用系统输入法 API，免费，延迟低 |
| 讯飞 REST API | `ApiSpeechRecognizer` | HTTP 接口，需申请 Key，支持会场音质 |

STT 结果经 `handleSpeechResult(text)` 统一进入后续意图识别 → 任务执行流程。

## 八、关键配置项

| 配置 | 位置 | 影响 |
|------|------|------|
| `wakeWordEnabled` | PreferenceManager | 是否自动启动语音唤醒服务 |
| `intentRecognizerEnabled` | PreferenceManager | 是否开启意图识别路由 |
| `smartCoordinatorEnabled` | PreferenceManager | 是否启用任务规划器 |
| `showAgentProcess` | PreferenceManager | 是否在对话中显示 THINKING/ACTION 气泡 |
| `maxSteps` | PreferenceManager | 每个子任务最大执行步数 |
| `porcupineAccessKey` | PreferenceManager | Picovoice API Key |
| `customPpnPath` | PreferenceManager | 自定义唤醒词模型路径 |
