# 协调器决策失败诊断指南

## 错误现象

错误信息：**"协调器连续决策失败，任务已停止"**

这个错误表示 SmartCoordinator 连续 3 次无法做出有效决策。

## 失败原因分析

根据代码分析（`SmartCoordinator.kt:52-140`），`decideNextStep()` 返回 `null` 的可能原因：

### 1. 协调器客户端未初始化 ⚠️
```kotlin
if (coordinatorClient == null) {
    Logger.w(Logger.AGENT, "SmartCoordinator model not configured")
    return null
}
```

**检查方法**：
- 查看 Logcat 是否有 `"SmartCoordinator model not configured"` 日志
- 确认协调器 API 配置完整（URL、API Key、Model Name）

### 2. API 调用异常 ⚠️
```kotlin
catch (e: Exception) {
    Logger.e(Logger.AGENT, "Decision making failed", e)
    return null
}
```

**可能的异常类型**：
- **网络异常**：无法连接到 API 服务器
- **认证失败**：API Key 错误或过期
- **超时异常**：请求超过 30 秒（`config.planningTimeout`）
- **模型错误**：模型名称错误或不支持

**检查方法**：
- 查看 Logcat 中的 `"Decision making failed"` 日志
- 查看异常堆栈信息

### 3. 模型返回空响应 ⚠️
```kotlin
private fun parseDecisionResponse(responseText: String): CoordinatorDecision? {
    val raw = responseText.trim()
    if (raw.isBlank()) return null
    // ...
}
```

**可能原因**：
- 模型没有生成任何输出
- API 返回了错误但没有抛出异常
- 响应被截断或格式错误

**检查方法**：
- 查看 Logcat 中的 `"[COORDINATOR] Decision thinking"` 日志
- 查看 `response.action` 的内容

运行配置检查脚本：

或手动检查：

**必需配置**：

- ✅ `coordinator_api_key` 不为空（对应模型的 key）
- ✅ `coordinator_model_name` 不为空
- ✅ `smart_coordinator_enabled` = true（如果想默认启用）

### 步骤 4：检查模型配置

确认使用的模型名称正确：

| 提供商 | 正确的模型名称 | 错误示例 |
|--------|---------------|---------|
| DeepSeek | `deepseek-chat`, `deepseek-reasoner` | `deepseek`, `deepseek-v3` |
| GLM | `glm-4-plus`, `glm-4-flash` | `glm4`, `glm-4` |
| Doubao | `doubao-pro-32k` | `doubao` |

### 步骤 5：检查 API Key 配置

协调器使用**特定提供商的 API Key**：

```kotlin
// WakeWordService.kt:195-200
val coordinatorApiKey = when {
    prefs.coordinatorModelName.startsWith("deepseek") -> prefs.coordinatorApiKeyDeepseek
    prefs.coordinatorModelName.startsWith("glm-") -> prefs.coordinatorApiKeyBigmodel
    prefs.coordinatorModelName.startsWith("doubao") -> prefs.coordinatorApiKeyDoubao
    else -> prefs.coordinatorApiKey
}
```

**检查要点**：
- 如果使用 `deepseek-chat`，需要配置 DeepSeek 的 API Key
- 如果使用 `glm-4-plus`，需要配置 BigModel 的 API Key
- 不要混用不同提供商的 API Key

## 常见问题和解决方案

### 问题 1：第一次请求就失败

**可能原因**：
1. ❌ API Key 错误或未配置
2. ❌ API URL 错误
3. ❌ 模型名称错误
4. ❌ 网络无法访问 API 服务器

**解决方案**：
1. 在设置中重新检查并保存配置
2. 使用 curl 测试 API 连接
3. 查看 Logcat 中的详细错误信息

### 问题 2：间歇性失败

**可能原因**：
1. ⚠️ 网络不稳定
2. ⚠️ API 服务器限流
3. ⚠️ 请求超时（默认 30 秒）

**解决方案**：
1. 检查网络连接
2. 增加超时时间（修改 `TaskPlannerConfig.planningTimeout`）
3. 更换 API 提供商

### 问题 3：模型返回空响应

**可能原因**：
1. ⚠️ System Prompt 过长导致模型无法生成
2. ⚠️ 截图过大导致请求失败
3. ⚠️ 模型配额用尽

**解决方案**：
1. 简化 System Prompt
2. 检查 API 账户余额
3. 查看模型提供商的错误日志

### 问题 4：协调器未初始化

**错误日志**：
```
W/AutoGLM: SmartCoordinator model not configured
```

**原因**：
- 协调器 API 配置不完整（URL、Key 或 Model 为空）

**解决方案**：
1. 打开 App 设置
2. 找到"智能协调器"区域
3. 填写完整的 API URL、API Key 和 Model Name
4. 点击保存
