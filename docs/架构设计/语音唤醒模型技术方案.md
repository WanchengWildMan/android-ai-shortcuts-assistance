# 轻量级个人语音唤醒模型技术方案

> 日期: 2026-04-12  
> 状态: 方案设计

## 1. 目标与约束

| 项目 | 要求 |
|------|------|
| **核心目标** | 用户喊几次唤醒词即可注册，仅响应当前用户的语音 |
| **说话人验证** | 双编码器架构: 唤醒词内容编码器 + 说话人声纹编码器，双阈值决策 |
| **模块化** | 更换唤醒词时只需重新录音+注册，不重新训练编码器 |
| **轻量级** | 双编码器共 ~202K 参数，可导出 ONNX 部署到 Android |
| **训练数据** | 正样本: 用户录音 5-10 条；负样本: edge-tts 合成 + 噪声增强 |
| **延迟** | 检测窗口 1.5s，步进 0.5s，单次推理 <10ms (CPU) |

## 2. 核心思路: 双编码器 + 双阈值决策

```
┌────────────────────────────────────────────────────────────────┐
│  阶段一: 预训练双编码器（一次性，使用 TTS 合成数据）                 │
│                                                                │
│  唤醒词编码器 (Prototypical Network)                              │
│    数据按 短语 分类 → 学习区分「说的是什么」→ encoder_best.pt       │
│                                                                │
│  说话人编码器 (GE2E Loss)                                         │
│    数据按 音色 分类 → 学习区分「谁在说话」→ speaker_encoder_best.pt │
│                                                                │
│  两个编码器同架构(~101K)、独立权重、独立训练                         │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│  阶段二: 双通道注册（秒级，仅需用户录音）                           │
│                                                                │
│  用户录音 ──→ 唤醒词编码器 ──→ 内容原型  ┐                        │
│           ──→ 说话人编码器 ──→ 声纹原型  ┤→ 模板 .npy             │
│                                         │  (可随时替换)           │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│  阶段三: 双通道实时检测                                          │
│                                                                │
│  麦克风流 ──→ Mel频谱                                            │
│               ├──→ 唤醒词编码器 → 内容相似度 ≥ 0.80?              │
│               └──→ 说话人编码器 → 声纹相似度 ≥ 0.75?              │
│                                                                │
│            两个条件都满足 → 唤醒!                                  │
│            内容不像 → 快速拒绝（不算声纹，省算力）                   │
└────────────────────────────────────────────────────────────────┘
```

**模块化体现**: 更换唤醒词 = 重做阶段二（几秒钟），双编码器和检测逻辑完全不变。

## 3. 系统架构

### 3.2 编码器模型（双编码器共享架构）

```
输入: Mel频谱图 [B, 1, 40, 150]  (1.5秒 @ 16kHz, 40维Mel, hop=160)

Conv2d(1→32, 3x3) → BN → ReLU → MaxPool(2)     [B, 32, 20, 75]
Conv2d(32→64, 3x3) → BN → ReLU → MaxPool(2)     [B, 64, 10, 37]
Conv2d(64→128, 3x3) → BN → ReLU → AdaptiveAvgPool(1)  [B, 128, 1, 1]
Linear(128→64) → L2 Normalize                     [B, 64]

两个编码器共享相同的 CNN 架构，但权重完全独立:
- WakeWordEncoder (~101K params): 学习区分「说的是什么」
- SpeakerEncoder  (~101K params): 学习区分「谁在说话」
```

### 3.3 唤醒词编码器训练 (Prototypical Network)

每个 episode:
1. 从 TTS 数据中随机选 N=10 个类（短语），每类取 K=5 个支持样本 + Q=5 个查询样本
2. 编码器对支持集编码，每类取均值得到**原型向量**
3. 编码器对查询集编码，计算与各原型的**余弦相似度**
4. 用交叉熵损失训练编码器区分不同短语

训练完成后编码器冻结，后续注册/检测只做推理。

### 3.4 说话人编码器训练 (GE2E Loss)

基于 Google 2018 年论文 "Generalized End-to-End Loss for Speaker Verification"。

**训练数据组织**: 将 TTS 数据按音色（说话人）分组，同一音色说的所有短语作为一个说话人的语料。14 种 TTS 音色 = 14 个虚拟说话人。

**每个 episode**:
1. 随机选 N=8 个说话人，每人取 M=6 条语音
2. SpeakerEncoder 对所有语音编码得到嵌入矩阵 [N, M, D]
3. 对每个说话人计算质心（排除当前样本的"排斥质心"防信息泄漏）
4. 构建 [N×M, N] 相似度矩阵: 每条语音与所有说话人质心的余弦相似度
5. GE2E Loss: 让对角线（自己的说话人）相似度最大化，其余最小化

**GE2E Loss 关键设计**:
- **可学习温度参数**: `w`（缩放）和 `b`（偏置），自适应调节相似度分布
- **排斥质心**: 计算说话人 j 的质心时，排除当前样本 i，防止自我参照导致的 trivial solution
- **梯度裁剪**: 模型梯度 max_norm=3.0，loss 参数梯度 max_norm=1.0，w 限制 ≥0.1

```python
# 排斥质心计算 (伪代码)
centroid_j_excl_i = (sum(embeddings[j]) - embeddings[j][i]) / (M - 1)
similarity[i][j] = w * cosine(embeddings[j][i], centroid_j_excl_i) + b
```

## 4. 负样本合成策略

| 类别 | 来源 | 数量 | 说明 |
|------|------|------|------|
| TTS 语音 | edge-tts 14种中文音色(6男8女) × 3音量级别 | 53短语 × 14音色 × 3音量 × 4变体 = 8,904 | 覆盖常见口令 |
| 白噪声 | numpy 生成 | 20条 | 高斯白噪声 |
| 粉红噪声 | scipy 滤波 | 20条 | 1/f 频谱 |
| 布朗噪声 | 随机游走 | 20条 | 累积随机过程 |
| 静音 | 极低幅度噪声 | 20条 | ~无声环境 |

**音色覆盖**: 普通话男声3个 + 女声3个 + 方言2个 + 粤语3个 + 台湾口音3个 = 14 音色

**音量级别**: 正常(+0%) / 小声(-30%) / 悄悄话级别(-60%)

**增强方法**: 高斯噪声叠加、变速(0.85x~1.15x)、随机增益(-20~+6dB)、简单混响、悄悄话模拟。

## 4.1 悄悄话唤醒支持策略

目标: 模型不依赖"声调/响度"，而是学习语言内容和音色的**频谱形状特征**。

### 数据层

1. **多音量级别 TTS**: edge-tts `volume` 参数合成 +0%/-30%/-60% 三个级别
2. **悄悄话模拟增强**: 高通滤波去基频(模拟声带不振动) + 气息噪声 + 低振幅
3. **极端增益范围**: random_gain 从 -20dB 到 +6dB，覆盖耳语到大声

### 模型层

4. **音量归一化(关键)**: 输入 Mel 频谱前统一归一化到固定 RMS=0.1
   - 功能: 彻底消除绝对响度作为特征，模型只能学频谱形状
   - 位置: `augment.normalize_volume()` → 在 `audio_to_mel()` 中调用
   - 所有路径统一: dataset.py / enroll.py / detect.py 均执行

### 效果预期

| 场景 | 音量归一化前 | 音量归一化后 |
|------|-------------|-------------|
| 正常说唤醒词 | Mel 能量高，易匹配 | 归一化后频谱形状匹配 |
| 悄悄话唤醒词 | Mel 能量极低，被忽略 | 归一化后频谱形状一致，可匹配 |
| 他人正常说唤醒词 | 可能误触发 | 频谱形状+音色不同，被拒绝 |

## 5. 检测流程（双通道）

```
麦克风 16kHz mono
    ↓
音频缓冲区 (deque, 24000 samples = 1.5s)
    ↓ 每 0.5s 触发一次
音量归一化 (RMS → 0.1)            ← 消除响度差异
    ↓
提取 Mel 频谱图 [1, 40, 150]
    ↓
┌─── 唤醒词编码器 → 内容嵌入 [64] ──→ 内容相似度 ≥ 0.80?
│                                        │
│    如果不像 → 直接拒绝（快速路径）        │
│                                        ↓ 通过
└─── 说话人编码器 → 声纹嵌入 [64] ──→ 声纹相似度 ≥ 0.75?
                                        │
                                        ↓ 通过
                                    唤醒! + 冷却 2s
```

**快速拒绝策略**: 先检查内容匹配（计算量小、误触发多），不像就跳过声纹检查，减少不必要的推理。

## 6. 说话人验证: 为什么能实现"只听我的声音"

### 6.1 单编码器 vs 双编码器

| 方案 | 原理 | 说话人区分能力 | 缺点 |
|------|------|---------------|------|
| 单编码器 | 嵌入混合内容+音色 | 弱，容易被相似语调骗过 | 一个向量装两种信息，互相干扰 |
| **双编码器** | 独立编码内容和音色 | **强，专注声纹特征** | 多一个模型，但架构相同 |

### 6.2 双编码器工作原理

1. **唤醒词编码器**: 在「按短语分类」的数据上训练，学到的嵌入**只关注内容**
   - 不同人说同一句话 → 嵌入接近（忽略音色差异）
   - 同一人说不同话 → 嵌入远离

2. **说话人编码器**: 在「按音色分类」的数据上训练，学到的嵌入**只关注声纹**
   - 同一人说不同话 → 嵌入接近（忽略内容差异）
   - 不同人说同一话 → 嵌入远离

3. **双阈值决策**:
   - 内容相似度 ≥ 0.80 → 说的确实是唤醒词
   - 声纹相似度 ≥ 0.75 → 说话的确实是注册用户
   - 两个都满足才触发唤醒

### 6.3 各场景预期效果

| 场景 | 内容相似度 | 声纹相似度 | 结果 |
|------|-----------|-----------|------|
| 本人说唤醒词 | 0.85-0.95 | 0.80-0.95 | 唤醒 |
| 本人悄悄话唤醒词 | 0.80-0.90 | 0.75-0.85 | 唤醒 |
| 他人说唤醒词 | 0.85-0.95 | 0.30-0.60 | 拒绝 (声纹不符) |
| 本人说其他话 | 0.20-0.50 | 0.80-0.95 | 拒绝 (内容不符) |
| 他人说其他话 | 0.20-0.50 | 0.30-0.60 | 拒绝 (两项都不符) |
| 环境噪声 | 0.05-0.20 | 0.05-0.20 | 拒绝 |

## 7. 使用流程

```bash
# 0. 安装依赖
cd wake_word && pip install -r requirements.txt

# 1. 合成负样本训练数据（约10分钟）
python generate_negatives.py

# 2. 训练双编码器
python train.py --mode both --device cpu  # 或 mps / cuda
# 也可分别训练:
#   python train.py --mode keyword   # 仅唤醒词编码器
#   python train.py --mode speaker   # 仅说话人编码器

# 3. 录制唤醒词（交互式，录10条）
python record_audio.py

# 4. 双通道注册（同时注册内容模板+声纹模板）
python enroll.py --wake-word 你的唤醒词
# 不需要说话人验证时:
#   python enroll.py --wake-word 你的唤醒词 --no-speaker

# 5. 实时双通道检测
python detect.py --wake-word 你的唤醒词
# 调整声纹阈值:
#   python detect.py --wake-word 你的唤醒词 --speaker-threshold 0.80

# 6. (可选) 导出 ONNX 供 Android 端部署
python export_onnx.py --mode both  # keyword / speaker / both
```

**更换唤醒词**: 只需重复步骤 3-4，双编码器无需重新训练。

**关闭说话人验证**: 注册时加 `--no-speaker`，检测端自动退化为纯内容匹配。

## 8. Android 集成方案

导出的 ONNX 模型可通过以下方式集成到现有项目:

1. 将 `wake_encoder.onnx`、`speaker_encoder.onnx` 和 `唤醒词.npy` 放入 `app/src/main/assets/`
2. 使用 ONNX Runtime Android (`com.microsoft.onnxruntime:onnxruntime-android`) 加载双模型
3. 实现一个新的 `WakeEngine` 子类（参考现有 `PorcupineWakeEngine`）
4. 在 `WakeEngine` 中实现双通道检测逻辑（先内容后声纹的快速拒绝策略）
5. 在 `WakeEngineManager` 中注册新引擎类型
6. 复用现有 AudioRecord 框架（16kHz, MONO, PCM16）
