# 执行步数配置说明

本文档详细说明 AutoGLM 助手中与任务执行步数相关的所有配置项。

## 📋 配置概览

系统中有**三个**与执行步数相关的配置：

| 配置名称 | 默认值 | UI 标签 | 状态 | 作用范围 |
|---------|--------|---------|------|---------|
| **maxSteps** | 100 | Agent 总操作步数上限 | ✅ 使用中 | 全局限制 |
| **maxCoordinatorSteps** | 20 | 协调器最大决策轮次 | ✅ 使用中 | 协调器模式 |
| **maxCorrections** | 2 | 最大纠正次数（已废弃） | ⚠️ 已废弃 | - |

## 1. maxSteps - Agent 总操作步数上限

### 基本信息
- **配置文件**: `PreferenceManager.kt`
- **常量名**: `KEY_MAX_STEPS`
- **默认值**: `100`
- **UI 位置**: 设置页面 → "Agent 设置" 部分
- **UI 标签**: "Agent 总操作步数上限" / "Agent Max Operation Steps"

### 含义
Agent 执行**单个任务**时的总操作步数上限。这是一个硬性约束，无论是否使用智能协调器，都会生效。

### 工作原理
每次 Agent 执行操作（如点击、输入、滑动等），`currentStep` 计数器会加 1。当 `currentStep >= maxSteps` 时，任务停止执行。

```kotlin
// 在 PhoneAgent.kt 中
while (coordinatorSteps < maxCoordinatorSteps && currentStep < agentConfig.maxSteps)
```

### 适用场景
- 防止任务陷入无限循环
- 控制单个任务的最长执行时间
- 避免过度消耗系统资源

### 调整建议
- **简单任务**（如发送消息）：可设置为 20-50
- **中等任务**（如浏览网页）：保持默认 100
- **复杂任务**（如多步骤操作）：可增加到 150-200

## 2. maxCoordinatorSteps - 协调器最大决策轮次 ⭐

### 基本信息
- **配置文件**: 
  - `PreferenceManager.kt`
  - `TaskPlannerConfig.kt`
- **常量名**: `KEY_MAX_COORDINATOR_STEPS`
- **默认值**: `20`
- **UI 位置**: 设置页面 → "智能协调器设置" 部分
- **UI 标签**: "协调器最大决策轮次" / "Max Coordinator Decision Rounds"

### 含义
使用智能协调器时，协调器每次任务的最大决策轮次。这是协调器特有的限制，仅在启用智能协调器时生效。

### 工作原理
每一轮决策包括以下步骤：

1. **分析阶段**：协调器接收当前截图和执行历史
2. **决策阶段**：协调器判断任务状态
   - `CONTINUE`: 继续执行，给出下一步指令
   - `COMPLETED`: 任务完成
   - `FAILED`: 任务失败
3. **执行阶段**：Agent 执行协调器给出的具体指令

完成一轮后，`coordinatorSteps` 加 1。

```kotlin
// 在 executeWithCoordinator() 中
var coordinatorSteps = 0
val maxCoordinatorSteps = agentConfig.plannerConfig?.maxCoordinatorSteps ?: 20

while (coordinatorSteps < maxCoordinatorSteps && currentStep < agentConfig.maxSteps) {
    coordinatorSteps++
    
    // 1. 获取截图
    val screenshot = screenCapture.capture()
    
    // 2. 协调器决策
    val decision = smartCoordinator?.decideNextStep(
        originalTask = task,
        executionHistory = executionHistory,
        screenshotBase64 = screenshot?.base64Data,
        language = agentConfig.language
    )
    
    // 3. 执行指令
    when (decision.status) {
        CoordinatorStatus.CONTINUE -> executeInstruction(decision.instruction)
        CoordinatorStatus.COMPLETED -> return decision.assessment
        CoordinatorStatus.FAILED -> return decision.assessment
    }
}
```

### 双重限制机制
协调器执行时**同时**受两个条件限制：

```kotlin
while (coordinatorSteps < maxCoordinatorSteps && currentStep < agentConfig.maxSteps)
```

- **coordinatorSteps < maxCoordinatorSteps**：决策轮次限制（默认 20）
- **currentStep < maxSteps**：总操作步数限制（默认 100）

**任一条件达到上限，任务执行都会停止。**

### 为什么需要两个限制？
- **maxCoordinatorSteps**：限制协调器的决策次数，防止反复规划
- **maxSteps**：限制 Agent 的实际操作次数，防止过度执行

### 示例场景

#### 场景 1：正常完成
```
coordinatorSteps = 5（决策了5轮）
currentStep = 25（Agent执行了25步操作）
结果：任务成功完成 ✅
```

#### 场景 2：达到决策轮次上限
```
coordinatorSteps = 20（达到maxCoordinatorSteps）
currentStep = 45（还未达到maxSteps）
结果：任务因决策轮次超限而停止 ⏹️
```

#### 场景 3：达到操作步数上限
```
coordinatorSteps = 15（还未达到maxCoordinatorSteps）
currentStep = 100（达到maxSteps）
结果：任务因操作步数超限而停止 ⏹️
```

### 调整建议
- **简单直接的任务**：可降至 10-15
  - 如："打开微信并发送消息"
  - 决策路径短，快速完成
  
- **中等复杂任务**：保持默认 20
  - 如："在淘宝搜索商品并添加购物车"
  - 可能需要多步导航和操作
  
- **复杂多步任务**：可增至 30-40
  - 如："对比多个购物平台的价格并下单"
  - 需要在多个应用间切换决策

## 3. maxCorrections - 最大纠正次数 ⚠️

### 基本信息
- **配置文件**: `PreferenceManager.kt`
- **常量名**: `KEY_MAX_CORRECTIONS`
- **默认值**: `2`
- **UI 位置**: 设置页面 → "智能协调器设置" 部分
- **UI 标签**: "最大纠正次数（已废弃）" / "Max Corrections (Deprecated)"
- **状态**: ⚠️ **已废弃**

### 原始设计
在旧版协调器流程中，该配置用于监督模式：
- 协调器预先规划多个子任务
- 监督器检查每个子任务的执行结果
- 如果执行错误，尝试纠正最多 `maxCorrections` 次

### 当前状态
**该功能在当前协调器流程中不再使用。** 新的协调器采用逐步决策模式，不再使用预先规划和监督机制。

保留此配置仅为向后兼容，建议忽略此设置。

## 🔧 实际应用示例

### 示例 1：微信发消息（简单任务）
```
推荐配置：
- maxSteps: 50
- maxCoordinatorSteps: 10

执行流程：
1. 协调器决策：打开微信
2. Agent执行：点击微信图标（currentStep: 1）
3. 协调器决策：搜索联系人
4. Agent执行：点击搜索框并输入（currentStep: 2-3）
5. 协调器决策：发送消息
6. Agent执行：点击联系人，输入消息，发送（currentStep: 4-6）

结果：coordinatorSteps=3, currentStep=6，任务完成 ✅
```

### 示例 2：淘宝购物（复杂任务）
```
推荐配置：
- maxSteps: 150
- maxCoordinatorSteps: 30

执行流程：
1. 协调器：打开淘宝
2. Agent：启动应用，等待加载（currentStep: 1-5）
3. 协调器：搜索商品
4. Agent：输入关键词，点击搜索（currentStep: 6-10）
5. 协调器：浏览商品列表
6. Agent：滚动查看，选择商品（currentStep: 11-20）
7. 协调器：查看商品详情
8. Agent：点击商品，滚动页面（currentStep: 21-30）
9. 协调器：添加购物车
10. Agent：选择规格，点击加购（currentStep: 31-35）

结果：coordinatorSteps=5, currentStep=35，任务完成 ✅
```

### 示例 3：达到上限的情况
```
配置：
- maxSteps: 100
- maxCoordinatorSteps: 20

执行流程：
协调器不断决策，但任务始终未完成
...
第 18 轮：currentStep=85
第 19 轮：currentStep=91
第 20 轮：currentStep=98（coordinatorSteps 达到 20）

结果：任务因决策轮次超限而停止 ⏹️
```

## 🎯 调试建议

### 如何判断哪个限制生效了？

查看日志输出：

```kotlin
// 在 PhoneAgent.kt 中
Logger.i(Logger.AGENT, "---------- Coordinator Step $coordinatorSteps ----------")
```

**如果看到**：
```
---------- Coordinator Step 20 ----------
Task execution stopped
```
→ 说明达到了 maxCoordinatorSteps 限制

**如果看到**：
```
---------- Coordinator Step 15 ----------
Max steps reached: 100
```
→ 说明达到了 maxSteps 限制

### 遇到任务未完成时的诊断

1. **任务提前停止**：
   - 检查是否触发 maxCoordinatorSteps
   - 尝试增加 maxCoordinatorSteps 值

2. **操作过多未完成**：
   - 检查是否触发 maxSteps
   - 尝试增加 maxSteps 值

3. **反复执行相同操作**：
   - 协调器可能陷入循环
   - 检查协调器的决策逻辑
   - 优化任务描述
