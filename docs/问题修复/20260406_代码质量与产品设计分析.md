**最严重：`MainActivity.kt` (3731行)**
- 本应只做 UI 渲染和导航的 Activity，实际承担了：
  - UI 层 + 设置页面（整个 SettingsScreen Compose 代码）
  - 服务绑定管理 + 权限申请 + 任务调度 + API Key 保存逻辑
- `MainScreen` Composable 函数接收 11 个 lambda 参数，职责不清晰
- API Key 按模型名称分发逻辑重复出现 6+ 次

### 1.2 职责不清的类

**`WakeWordService` (1542行)** 同时管理：
- 前台服务生命周期
- 唤醒引擎管理
- 语音识别
- PhoneAgent 初始化和回调绑定（核心逻辑超过 240 行）
- 协调器消息转发
- 5种悬浮窗管理
- IME 键盘管理、通知栏更新

**`PhoneAgent` (1160行)**：
- 定义了 **23 个回调属性**，严重的回调地狱
- 同时管理意图识别、Prompt 优化、协调器执行、直接执行四种模式

### 1.3 严重的重复代码

**问题一：API Key Provider 分发逻辑重复 19 次**

```kotlin
when {
    modelName.startsWith("deepseek") -> prefs.xxxApiKeyDeepseek
    modelName.startsWith("glm-") -> prefs.xxxApiKeyBigmodel
    modelName.startsWith("doubao") -> prefs.xxxApiKeyDoubao
    else -> prefs.xxxApiKey
}
```
出现位置：WakeWordService.kt(3处)、MainActivity.kt(12处)、ShortcutEditDialog.kt(1处)

**问题二：`startForegroundService` 启动代码重复 6 次**
- MainActivity.kt 中 5 处近乎相同的启动逻辑

**问题三：`startForeground` 版本适配代码重复 4 次**
- WakeWordService.kt 中两段 30 行的几乎相同代码

**问题四：PreferenceManager 属性模式重复**
- 每个模块 4 个 provider-specific key 属性，共约 48 个高度相似 var

### 1.4 错误处理不统一

- ~~`e.printStackTrace()` / `Log.e(TAG,...)` / `Logger.e(...)` / `android.util.Log.e(...)` 四种方式并存~~ **已修复：全部统一为 Logger**
- 协程异常无统一处理
- 没有错误收集和上报机制

### 1.5 配置/常量管理散乱

- PreferenceManager 约 110 个常量堆在同一个 companion object
- 默认 API URL 在 PreferenceManager 和 ModelConfig 中各自定义，口径不一
- IME 坐标硬编码（HARD 标记）

### 1.6 ViewModel/Repository 分层

- 没有 Repository 层，ViewModel 直接操作文件
- 消息同步存在竞态风险

### 1.7 依赖注入

- 完全手动实例化，无 DI 框架
- 全局可变单例（App.instance, WakeWordService.instance），线程安全风险

### 1.8 命名一致性

- ~~日志 TAG 混用 4+ 种风格~~ **已修复：统一为 Logger 模块常量**
- `run()` vs `executeTask()` 方法名语义重叠
- Coordinator / Planner / TaskPlanner 概念混用

## 三、产品不足分析

### 3.1 跨会话记忆
- 每次新任务清空 conversationHistory
- TaskSnapshot 已定义但未集成
- 无任务历史摘要/跨会话上下文注入

### 3.2 个人偏好注入
- 仅存储应用配置，无用户行为偏好
- 无行为日志采集和偏好学习

### 3.3 Skill/个人模板
- 快捷指令支持参数化，但无云端同步
- 无"从执行历史自动生成快捷指令"能力
- 无版本管理和分享

### 3.4 任务失败恢复
- 支持用户干预恢复（resumeWithIntervention）
- 但无自动重试、无 checkpoint/回滚、无网络降级

### 3.5 多轮交互
- 仅支持"Agent问→用户答"单向
- 无确认前执行预览（敏感操作）
- 语音不支持连续对话

### 3.6 用户反馈机制
- **基本空白**：无点赞/点踩、无操作标注

### 3.7 任务安全边界
- 无操作白名单/黑名单
- 无金额/敏感信息识别
- Shell 命令无沙箱
- 无操作速率限制
