# 📱 无障碍服务部署指南

## 🎯 部署步骤

### 步骤1: 安装两个应用

```bash
# 方式1: 使用 Gradle 自动安装（推荐）
./gradlew installDebug

# 方式2: 使用安装脚本
./install_both.sh

# 方式3: 手动安装
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r provider/build/outputs/apk/debug/provider-debug.apk
```

### 步骤2: 启用无障碍服务

1. 打开 **系统设置** → **无障碍**
2. 找到 **无障碍服务提供者** (Accessibility Provider)
3. 点击开启服务
4. 允许权限（**注意：这是系统级权限，请仔细阅读提示**）

### 步骤3: 验证服务状态

在主应用中，无障碍功能会自动检测并使用 provider 服务。可以通过以下代码验证：

```kotlin
import com.autoglm.assistant.accessibility.UIHierarchyManager

// 检查服务是否启用
val manager = UIHierarchyManager.getInstance(context)
val isEnabled = manager.isAccessibilityServiceEnabled()
Log.d("TEST", "无障碍服务状态: $isEnabled")

// 执行点击测试
if (isEnabled) {
    manager.performClick(100f, 200f)
}
```

## 📦 应用说明

### 主应用 (com.autoglm.assistant)
- **功能**: AutoGLM 智能助手
- **包名**: `com.autoglm.assistant`
- **用途**: 日常使用的主应用

### Provider 应用 (Accessibility Provider)
- **功能**: 无障碍服务提供者
- **包名**: `com.autoglm.assistant.provider`
- **用途**: 独立提供无障碍能力，降低主应用被检测风险
- **注意**: 
  - ⚠️ 必须保持安装，卸载会导致主应用功能异常
  - ⚠️ 启用后会一直在后台运行
  - ⚠️ 不要禁用电池优化，否则服务可能被系统杀掉

## 🔍 故障排查

### 问题1: 主应用提示"无障碍服务未启用"

**解决方案**:
1. 确认 provider 应用已安装: `adb shell pm list packages | grep provider`
2. 进入系统设置检查无障碍服务是否启用
3. 尝试关闭后重新启用服务
4. 重启主应用

### 问题2: 点击操作无响应

**解决方案**:
1. 检查 provider 服务是否在运行:
   ```bash
   adb shell dumpsys accessibility | grep Accessibility
   ```
2. 查看 provider 日志:
   ```bash
   adb logcat -s AccessibilityProvider ProviderBindService
   ```
3. 确认坐标是否在屏幕范围内
4. 检查目标应用是否允许无障碍服务操作

### 问题3: 服务连接失败

**解决方案**:
1. 检查主应用日志:
   ```bash
   adb logcat -s UIHierarchyManager
   ```
2. 查看绑定状态（日志中搜索 "AIDL 服务绑定"）
3. 确认 provider action 一致: `com.autoglm.assistant.provider.IAccessibilityProvider`
4. 尝试重启两个应用

### 问题4: Provider APK 签名错误

如果安装时提示 `INSTALL_PARSE_FAILED_NO_CERTIFICATES`:

**原因**: 使用了 release 版本的 APK 但未配置签名

**解决方案**:
```bash
# 方式1: 使用 Gradle 自动安装（推荐）
./gradlew installDebug

# 方式2: 使用修复后的脚本（使用 debug APK）
./install_both.sh

# 方式3: 手动安装 debug 版本
adb install -r provider/build/outputs/apk/debug/provider-debug.apk
```

### 问题5: Provider APK 不存在

如果主应用提示找不到 `accessibility_provider.apk`:

```bash
# 重新编译 provider 模块（会自动复制 APK 到 assets）
./gradlew :provider:assembleRelease

# 检查文件是否存在
ls -lh app/src/main/assets/accessibility_provider.apk
```

## 🔧 开发调试

### 修改 provider 后重新部署

```bash
# 1. 清理旧编译产物
./gradlew clean

# 2. 重新编译 provider（自动复制到 assets）
./gradlew :provider:assembleRelease

# 3. 编译并安装两个应用
./gradlew installDebug
```

### 版本管理

Provider APK 版本由 `app/src/main/assets/accessibility_version.txt` 控制：
- 主应用会检查版本号
- 如果 provider 版本过低，会提示升级
- 修改 `provider/build.gradle.kts` 中的 `versionName` 后，同步更新 `accessibility_version.txt`

---

## ⚠️ 重要提示

1. **系统权限**: 无障碍服务是敏感权限，需要用户在系统设置中手动授予
2. **独立应用**: Provider 和主应用完全独立，通过 AIDL 跨进程通信
3. **持久运行**: Provider 服务启用后会常驻后台，请在电池设置中允许后台运行
4. **版本同步**: 更新 provider 时，确保版本号与 `accessibility_version.txt` 一致
5. **卸载顺序**: 先卸载主应用，再卸载 provider；反之可能导致主应用异常
